# Tabsurd: технологии расширения

Статус: решения приняты 2026-10-11.
Связанные документы: `docs/extension/specification.md` (требования расширения), `docs/specification.md` (идея и общие решения), `video-analyzer/docs/local_service/local_service.md` (технологии локального сервиса — там, а не здесь).

## 1. Сводка

| Что | Решение |
|---|---|
| Язык | TypeScript |
| Сборка | WXT (на Vite), pnpm |
| Страницы расширения | React |
| Компоненты и оформление | MUI (Material UI), Material Design |
| Архитектура кода | Feature-Sliced Design |
| Плашка и кнопки на сайтах | без фреймворка, в Shadow DOM |
| Данные расширения | IndexedDB через Dexie |
| Настройки | `chrome.storage.sync` и `chrome.storage.local` |
| Графики | ECharts |
| Таблицы и данные | TanStack Table, Virtual, Query |
| Клиент API локального сервиса | `openapi-typescript` + `openapi-fetch` |
| Связь с сервером синхронизации | HTTP-запросы из фонового скрипта, без WebSocket |
| Установка | без магазина: распакованное расширение в режиме разработчика |
| Тесты | Vitest |

Все зависимости собираются в бандл расширения; из интернета расширение ничего не загружает.

## 2. Решения

### 2.1. Сборка — WXT, pnpm

Точки входа задаются файлами: скрипты на сайтах, страницы, фоновый скрипт. WXT сам пишет `manifest.json`, перезагружает расширение при правках и умеет показывать интерфейс на чужой странице в Shadow DOM. Пакеты ставит pnpm: каждый пакет хранится на диске один раз, а в `node_modules` проектов — ссылки на него, поэтому установка быстрее, чем у npm, и антивирусу меньше файлов для проверки. Версия pnpm закреплена полем `packageManager` в `package.json`, запускается через corepack (`corepack enable pnpm`).

### 2.2. Страницы расширения — React

Страницы — это большие списки с фильтрами, сортировкой и графиками. У React для этого больше всего готовых библиотек, и WXT поддерживает его официально.

- Таблицы — TanStack Table, прокрутка десятков тысяч строк — TanStack Virtual.
- Загрузка и кеш данных локального сервиса — TanStack Query.
- Графики — ECharts: тепловая карта «день × час», календарь, масштабирование, большие объёмы данных.
- Компоненты — **MUI (Material UI)**: кнопки, списки, таблицы, диалоги, вкладки, уведомления в стиле Material Design. Самая зрелая библиотека Material Design для React: полный набор компонентов, тема (цвета, светлая и тёмная), значки `@mui/icons-material`. Шрифт Roboto — пакетом `@fontsource/roboto` внутри бандла, не с Google Fonts. Плашка на сайтах MUI не использует (раздел 2.4), но повторяет цвета темы.

### 2.3. Архитектура — Feature-Sliced Design

Код расширения раскладывается по слоям FSD. Слой может импортировать только слои ниже себя, а слайсы одного слоя друг друга не импортируют.

| Слой | Что в нём у Tabsurd |
|---|---|
| `app` | запуск каждой точки входа: провайдеры React, роутер страниц, инициализация Dexie и настроек |
| `pages` | страницы: «Сохранённые», «Окна», «Восстановление», «Топ», «Статистика обо мне», «Итоги», «Настройки», «Первый запуск» |
| `widgets` | крупные блоки страниц: таблица видео, тепловая карта, список окон, очередь скачивания |
| `features` | действия пользователя: сохранить и закрыть группу, вернуть, «Не закрывать», скачать, поставить симпатию, подключиться к video-analyzer |
| `entities` | сущности: окно, группа, вкладка, снимок, видео, канал, скачивание — модель, хранилище, отображение |
| `shared` | общее без предметной области: клиент API локального сервиса, обёртка над Dexie и `chrome.*`, UI-компоненты, работа со временем (сутки с 6:00) |

Внутри слайса — сегменты `ui`, `model`, `api`, `lib`, наружу он отдаёт только публичный `index.ts`.

Точки входа WXT (`entrypoints/`) остаются тонкими: фоновый скрипт, скрипты на сайтах и страницы только вызывают код из `app`. Фоновый скрипт и плашка без React тоже пользуются слоями `features`, `entities` и `shared`, просто без сегмента `ui` на React.

Правила импорта проверяются автоматически линтером (например, Steiger или правила ESLint для FSD).

### 2.4. Плашка на сайтах — без фреймворка

Скрипт учёта просмотров встраивается во все страницы и рамки, где может быть видео, поэтому он должен быть лёгким: React разбирался бы в каждой рамке. Плашка — строка текста и несколько кнопок, на обычном TypeScript. Сложное, например выбор папки при скачивании, открывается на странице расширения. Shadow DOM защищает плашку от стилей сайта. Если плашка разрастётся — Preact.

### 2.5. Хранилище

- **IndexedDB через Dexie** — сохранённые окна и группы, недавно закрытые вкладки, снимки окон, очередь синхронизации, наблюдения до отправки в локальный сервис. Это основная копия данных профиля.
- **`chrome.storage.sync` и `chrome.storage.local`** — настройки (`docs/extension/specification.md`, раздел 1.3). Изменение сразу видят все части расширения.

Вкладки и страницы расширения одного браузера синхронизируются через это хранилище, без сервера. Скрытая вкладка не перерисовывается; при возврате на неё перечитывает данные из хранилища.

### 2.6. Связь с серверами

- **Локальный сервис** — HTTP на `http://127.0.0.1:<порт>/api/…` со страниц и из фонового скрипта расширения; скрипт на странице сайта сам в `localhost` не ходит. Договор — копия `api/openapi.yaml` репозитория video-analyzer в `extension/api/local-service.openapi.yaml`, типы из неё — в `src/shared/api/local-service/schema.d.ts`. Оба файла в git, чтобы расширение собиралось без video-analyzer рядом.
- **Обновление договора** — `pnpm api:update`: копирует файл из video-analyzer и заново строит типы. Путь к video-analyzer — в `extension/.env.local` (не в git): `VIDEO_ANALYZER_DIR=…`; без него команда объясняет, что задать.
- **Сервер синхронизации** — HTTP-запросы, без постоянного соединения: при запуске Chrome, при открытии страницы расширения, при пробуждении компьютера из сна и по будильнику раз в 5–10 минут (`docs/sync_server/specification.md`, раздел 3). Будильник — `chrome.alarms`; пробуждение из сна определяется по `chrome.idle` и по пропуску будильника.
- **Service worker спит, когда нечего делать**: его будят события вкладок, кнопок и будильник.

### 2.7. Учёт просмотров на странице

- Скрипт на сайтах — во всех рамках (`all_frames`, `match_about_blank`). События плеера (`play`, `pause`, `seeking`, `timeupdate` и др.) не всплывают, поэтому слушаются на `document` в фазе перехвата.
- Фоновая вкладка определяется по `document.visibilityState`.
- Видео внутри закрытого Shadow DOM обычный скрипт не видит; если такие сайты встретятся — отдельный скрипт в контексте страницы.

### 2.8. Установка без магазина

Расширение не публикуется в Chrome Web Store (там нужен платный аккаунт разработчика): оно ставится распакованным в режиме разработчика.

- **Постоянный ID** задаётся ключом в манифесте (`key`). Он нужен для входа через Google и для проверки отправителя в локальном сервисе.
- **Обновление** — вручную: собрать новую версию и нажать «Обновить» на странице расширений в каждом профиле.
- Chrome может иногда напоминать, что включён режим разработчика.
