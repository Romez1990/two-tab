# Tabsurd: сервер синхронизации

Статус: проект, 2026-10-11.
Связанные документы: `docs/specification.md` (идея, части и режимы), `docs/extension/specification.md` (требования расширения, раздел 6), `docs/sync_server/technologies.md` (технологии сервера), `docs/extension/technologies.md` (технологии расширения).

Удалённый сервер на своём VPS. Хранит открытые окна и вкладки, сохранённые окна и группы, недавно закрытые вкладки и снимки окон, чтобы у одного аккаунта они были одинаковыми на всех компьютерах. Не путать с **локальным сервисом** video-analyzer (`video-analyzer/docs/local_service/local_service.md`): тот на компьютере пользователя, и друг с другом они не общаются.

---

## 1. Вход и аккаунты

- Расширение получает токен Google-аккаунта профиля Chrome (`chrome.identity.getAuthToken`).
- Сервер проверяет у Google, что токен выдан именно расширению Tabsurd, и берёт постоянный номер Google-аккаунта. Дальше сервер выдаёт свой токен, чтобы не обращаться к Google на каждый запрос.
- **Только разрешённые аккаунты.** Список разрешённых адресов почты — в настройках сервера; остальным отказ.
- Разовая подготовка: проект в Google Cloud с OAuth client типа «Chrome extension» и постоянный ID расширения (ключ в манифесте).
- Профиль без входа в Chrome синхронизацию не включает и работает только локально.

## 2. Модель данных

| Таблица | Что в ней |
|---|---|
| `accounts` | номер Google-аккаунта, адрес почты |
| `devices` | компьютеры и профили аккаунта: название. Нужны, чтобы снимки окон хранились по компьютерам |
| `records` | все синхронизируемые записи |

Поля `records`:

| Поле | Смысл |
|---|---|
| аккаунт, коллекция | `open_window`, `open_tab`, `saved_group`, `closed_tab`, `window_snapshot` |
| номер записи | UUID, создаёт расширение |
| номер изменения | растёт в пределах аккаунта, выдаёт сервер |
| поля и время изменения каждого поля | для слияния по полям; время — по часам сервера |
| пометка «удалено» | удаление тоже синхронизируется. Пометки хранятся без срока: около 100 байт каждая, и компьютер, который долго не включали, всё равно узнает об удалениях |

**Слияние по полям.** Для каждого поля побеждает более позднее изменение. **Время изменения — по часам сервера**, а не компьютера: часы компьютеров могут отставать или спешить. Каждый ответ сервера содержит его время; расширение считает поправку «время сервера − время компьютера» (с учётом половины времени запроса) и ставит действию время в момент действия с этой поправкой. Без сети используется последняя известная поправка: часы уходят медленно. Время из будущего сервер заменяет своим текущим. Функция слияния и схемы записей — в `sync-core/`: одну и ту же функцию вызывают сервер (при приёме изменений) и расширение (при получении чужих изменений поверх своих неотправленных). Иначе компьютеры могли бы молча разойтись.

**Сквозное шифрование** не делается, но модель его допускает: значение каждого поля можно будет шифровать отдельно, оставив открытым время изменения, и сервер продолжит сливать по полям, не видя содержимого.

## 3. Протокол

- **Отправка:** `POST /sync/push` — пачка изменений. Сервер сливает их с хранимыми и выдаёт номера изменений.
- **Получение:** `GET /sync/changes?since=N` — всё, что изменилось после номера N.
- **Когда расширение спрашивает сервер:** при запуске Chrome, при открытии страницы расширения, при пробуждении компьютера из сна и по будильнику раз в 10 минут; отправляет — сразу после изменения, если сервер доступен. Доступность проверяется запросом `GET /health`; если он не прошёл, изменения остаются в очереди. Задержка в несколько минут допустима: за двумя компьютерами одновременно работают редко.
- **WebSocket нет.** Если понадобятся мгновенные обновления, его можно добавить: он только сообщал бы «есть изменения до номера N» и вызывал тот же `/sync/changes`, протокол бы не менялся.
- **Открытые окна и вкладки** — коллекции `open_window` (постоянный номер окна, место в порядке окон) и `open_tab` (окно, место в окне, адрес, заголовок, группа, закреплена ли). Окно или вкладка, закрытые на одном компьютере, получают пометку «удалено» и закрываются на остальных. Сливаются по тем же правилам, что остальные записи: если два компьютера меняли вкладки без связи, открытое на любом остаётся открытым везде, закрытое на любом закрывается везде, а для каждого поля побеждает последнее изменение. Размер и положение окон на экране не синхронизируются — у компьютеров разные мониторы. Как расширение применяет пришедшие изменения — `docs/extension/specification.md`, раздел 2.6.
- **Снимки окон** уходят на сервер, когда попадают в историю, и хранятся по тем же правилам, что в расширении (`docs/extension/specification.md`, раздел 2.2).

**Договор** — свой `openapi.yaml` у сервера синхронизации, отдельно от договора локального сервиса. Если появится WebSocket, его сообщения описываются схемами в этом же файле.

## 4. Отложено

- **Чистка пометок «удалено»** — если база начнёт занимать слишком много места. Удалять пометки, которые старше последней синхронизации каждого устройства аккаунта: их уже получили все.
- **Развёртывание на VPS** (Docker, HTTPS, домен, резервные копии) — не планируется, пока не будет готов сам сервер.
