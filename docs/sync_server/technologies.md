Связанные документы: `docs/sync_server/specification.md` (требования), `docs/extension/technologies.md` (технологии расширения).

## 1. Технологии

| Что | Решение |
|---|---|
| Язык | TypeScript |
| Фреймворк | **NestJS**: модули, контроллеры, сервисы, IoC-контейнер — архитектуру задаёт фреймворк |
| Среда | **Deno 2**. Первым шагом каркаса проверяется, что в Deno работают внедрение зависимостей NestJS (метаданные типов, `emitDecoratorMetadata`), MikroORM и `nestjs-zod`. Если нет — **Bun** |
| База | **PostgreSQL** |
| ORM | **MikroORM**: сущности с декораторами, внедряемые репозитории, Unit of Work — все изменения запроса сохраняются одной транзакцией, поэтому пачка изменений от расширения применяется целиком или никак |
| Схемы и OpenAPI | **`nestjs-zod`**: DTO и OpenAPI строятся из zod-схем, которые лежат в `sync-core/` и общие с расширением |

**Зависимости — в `deno.json`.** Если придётся перейти на Bun или Node, их перенесут в `package.json`: импорты `npm:` и `jsr:` переписываются, пакеты JSR заменяются аналогами из npm. Чтобы переход был проще, в коде приложения нет вызовов `Deno.*`.
